# AI 修图平台用户端 PRD

- 文档版本：v0.1
- 更新日期：2026-07-29
- 适用范围：`front/client`
- 当前阶段：需求设计，接口使用 Mock，不包含编码实现

## 1. 项目背景

用户在咸鱼购买 AI 图片服务后，卖家向用户发送 Web 平台地址和兑换码。用户通过邮箱和密码注册或登录，在平台中兑换可用次数，随后使用文生图、图生图以及后续扩展的 AI 修图能力。

本阶段只设计用户端 Client，管理端、兑换码生成、真实次数扣减、AI 接口调用和后台任务执行不在本阶段实现范围内。

## 2. 产品目标

### 2.1 核心目标

1. 让用户通过简单的邮箱和密码完成注册、登录。
2. 让用户使用咸鱼订单获得的兑换码领取可用次数。
3. 在用户拥有可用次数后，开放文生图、图生图等功能。
4. 在所有收费操作提交前显示预计消耗，并由服务端完成最终校验。
5. 让用户能够持续查看任务进度、生成结果和次数变化。

### 2.2 非目标

1. 不在前端保存或暴露 AI API URL、Key。
2. 不在本阶段开发管理端。
3. 不开发网页版 Photoshop 或复杂图片编辑器。
4. 不重复建设完整的支付、订单和成本管理系统。
5. 不在浏览器本地保存用户的真实权益余额。

## 3. 核心原则

1. 兑换码只能成功兑换一次。
2. 同一账号可以继续兑换新的兑换码。
3. 兑换获得的次数绑定用户账号，不绑定某一台浏览器。
4. 浏览器只保存登录会话和设备标识，用于保持登录和辅助风控。
5. 用户更换浏览器或清除缓存后，重新登录仍能恢复账号次数。
6. 前端显示的次数仅用于展示，最终校验、预占、扣减和退回都由服务端完成。
7. 生图 URL 和 Key 不得出现在前端代码、LocalStorage 或浏览器直连请求中。

## 4. 用户流程

```text
咸鱼购买
  → 获得平台网址和兑换码
  → 注册或登录
  → 兑换使用次数
  → 选择图片能力
  → 上传素材并填写需求
  → 优化和确认提示词
  → 查看预计消耗
  → 提交任务
  → 查看结果
```

## 5. 用户状态

| 状态 | 可执行操作 |
| --- | --- |
| 未登录 | 登录、注册 |
| 已登录但未兑换 | 查看主界面、兑换次数，不能提交收费任务 |
| 有可用次数 | 使用已授权的文生图、图生图和提示词优化能力 |
| 次数不足 | 查看历史任务和结果、兑换新码，不能提交收费任务 |
| 账号异常 | 查看异常原因、退出登录 |

## 6. 信息架构

### 6.1 页面路由建议

| 页面 | 路由建议 | 主要职责 |
| --- | --- | --- |
| 登录/注册 | `/auth` | 登录、注册、恢复会话 |
| 主界面 | `/app` | 权益状态、快捷入口、最近任务 |
| 文生图 | `/app/text-to-image` | 文本生成图片 |
| 图生图 | `/app/image-to-image` | 上传图片并完成图片生成或修改 |
| 任务记录 | `/app/tasks` | 查看全部历史任务 |
| 任务详情 | `/app/tasks/:taskId` | 查看进度、结果和次数记录 |
| 账号中心 | `/app/account` | 用户信息、使用次数、兑换和消费记录 |

### 6.2 全局导航

顶部导航包括：

- 左侧：品牌名称。
- 中间：文生图、图生图、任务记录。
- 右侧：剩余次数、兑换码兑换、用户菜单。

所有受保护页面都需要校验登录状态。未登录用户访问受保护页面时跳转到登录页，并在登录成功后返回原页面。

## 7. 页面需求

### 7.1 登录/注册页

登录与注册使用同一页面，通过分段控件切换，不制作营销落地页。

#### 登录字段

- 邮箱。
- 密码。
- 在此设备保持登录。

#### 注册字段

- 邮箱。
- 密码。
- 确认密码。
- 同意服务协议和隐私说明。

#### 交互要求

1. 输入框必须有始终可见的标签，不能只使用占位文字。
2. 密码输入框支持显示和隐藏密码。
3. 邮箱在失焦后校验格式。
4. 密码至少 8 位。
5. 注册成功后自动登录并进入主界面。
6. MVP 暂不做邮箱验证码。
7. 忘记密码在 MVP 阶段可提示联系管理员处理，邮件重置放入后续版本。

### 7.2 主界面

主界面根据用户的权益状态展示不同内容。

#### 未兑换状态

- 显示“使用兑换码解锁图片功能”的主要引导。
- 文生图和图生图入口保持可见，但标记为尚未解锁。
- 用户可以进入功能页面查看输入项，但不能提交收费动作。

#### 有可用次数

- 显示当前剩余次数。
- 展示文生图、图生图快捷入口。
- 展示最近任务和任务状态。

#### 次数不足

- 保留历史任务和历史结果访问能力。
- 突出“兑换新码”操作。
- 不清空用户已保存的任务草稿。

### 7.3 兑换码兑换

兑换功能通过右上角按钮打开弹窗。

#### 弹窗内容

- 兑换码输入框。
- 兑换按钮。
- 简短规则说明。
- 最近一次兑换结果。

#### 成功反馈

```text
兑换成功
已增加 10 次，当前剩余 12 次
```

#### 异常状态

- 兑换码无效。
- 兑换码已被使用。
- 兑换码已过期。
- 兑换码不适用于当前产品。
- 操作过于频繁。
- 网络连接失败。
- 请求已成功处理，但响应丢失。

同一个兑换请求必须支持幂等处理。用户重复点击、刷新页面或网络重试时，不能重复增加次数。

### 7.4 文生图工作台

#### 输入内容

- 提示词。
- 可选参考图片。
- 图片比例。
- 生成数量。
- 可选输出风格。

#### 推荐流程

```text
填写描述
  → 优化提示词
  → 用户确认提示词
  → 查看本次预计消耗
  → 生成图片
```

提示词优化结果按以下结构展示：

- 主体。
- 场景。
- 风格。
- 构图。
- 细节。
- 禁止内容。
- 输出规格。

用户可以编辑、重新优化和确认提示词。确认后的提示词形成当前任务的版本快照。

### 7.5 图生图工作台

#### 输入内容

- 一张或多张原始图片。
- 一张或多张参考图片。
- 修改要求。
- 图片比例。
- 生成数量。
- 参考强度等后续可选参数。

#### 参考图片用途

用户上传参考图后，需要为每张图片选择用途：

- 风格参考。
- 构图参考。
- 人物或服装参考。
- 局部细节参考。

原始图片与参考图片必须分区展示，避免用户或模型无法判断每张图片的用途。

### 7.6 任务记录

任务列表需要展示：

- 任务类型。
- 创建时间。
- 素材缩略图。
- 当前状态。
- 本次消耗。
- 结果数量。

任务状态包括：

- 草稿。
- 等待提交。
- 排队中。
- 处理中。
- 已完成。
- 部分失败。
- 失败且次数已退回。
- 已取消。

### 7.7 任务详情与结果

结果页需要支持：

- 查看任务输入参数。
- 查看已确认的提示词。
- 查看当前任务进度。
- 原图与生成结果对比。
- 图片放大预览。
- 单张下载。
- 全部下载。
- 复用当前参数创建新任务。
- 再次生成。

再次生成属于新的收费动作，必须重新显示预计消耗并进行最终校验。

### 7.8 账号中心

账号中心展示：

- 用户邮箱。
- 当前剩余次数。
- 兑换记录。
- 消费记录。
- 任务退款记录。
- 当前登录设备和退出登录操作。

## 8. 次数校验与扣减

### 8.1 收费动作

不是所有接口操作都消耗次数。

登录、注册、图片上传、查看历史等操作不扣次数。提示词优化、文生图、图生图等操作是否收费，由服务端策略决定。

MVP 可以规定每次成功提交生成任务消耗 1 次，但前端必须读取接口下发的 `cost`，不能在代码中写死。

### 8.2 提交流程

所有收费按钮统一遵循以下流程：

1. 页面请求服务端获得本次预计消耗和当前余额。
2. 按钮显示具体文案，例如“生成图片 · 消耗 1 次”。
3. 用户点击后，最终提交接口再次原子校验可用次数。
4. 校验通过后，服务端预占或扣减次数并创建任务。
5. 前端根据接口响应更新余额。
6. 平台原因导致任务失败时，服务端退回次数。
7. 前端展示退款结果和最新余额。

前端预检查只用于界面提示，不能代替最终提交接口的服务端校验。否则用户同时打开多个页面时可能发生次数透支。

### 8.3 按钮状态

收费按钮需要覆盖：

- 正常可提交。
- 正在获取报价。
- 次数不足。
- 正在提交。
- 提交成功。
- 提交失败。
- 任务创建成功但后台处理中。

请求进行中需要禁用按钮，防止重复提交。

## 9. Mock 接口需求

| 模块 | 接口职责 |
| --- | --- |
| Auth | 注册、登录、退出、恢复当前会话 |
| Profile | 用户资料和设备会话 |
| Entitlement | 剩余次数、可用功能、账号状态 |
| Redemption | 兑换码兑换和兑换记录 |
| Usage Quote | 返回操作成本、当前余额和是否可提交 |
| Usage Ledger | 查询兑换、消费和退款流水 |
| Assets | 图片上传、删除、排序和设置用途 |
| Prompt | 提示词优化、保存和确认 |
| Generation | 提交文生图和图生图任务 |
| Jobs | 查询排队、进度、成功、失败和退款状态 |
| History | 任务列表、任务详情和结果下载 |

### 9.1 Mock 必须覆盖的业务错误

- `AUTH_REQUIRED`：用户未登录。
- `ACCOUNT_DISABLED`：账号不可用。
- `REDEMPTION_REQUIRED`：尚未兑换权益。
- `INSUFFICIENT_CREDITS`：可用次数不足。
- `CODE_INVALID`：兑换码无效。
- `CODE_USED`：兑换码已经使用。
- `CODE_EXPIRED`：兑换码已过期。
- `CODE_PRODUCT_MISMATCH`：兑换码产品不匹配。
- `RATE_LIMITED`：操作过于频繁。
- `DUPLICATE_REQUEST`：重复提交。
- `JOB_FAILED_CREDITS_REFUNDED`：任务失败且次数已退回。

### 9.2 Mock 场景

Mock 数据不能全部即时成功，需要支持：

- 登录过期。
- 兑换成功和各类兑换失败。
- 上传部分失败。
- 获取消耗报价失败。
- 次数不足。
- 生成任务排队。
- 生成进度变化。
- 部分图片成功。
- 生成任务超时。
- 失败后次数退回。
- 页面刷新后任务继续处理。

## 10. 视觉设计方向

产品定位为安静、可信、图片优先的创作工具，不采用常见的 AI 紫色渐变或纯聊天机器人布局。

### 10.1 色彩

- 页面背景：`#F6F7F9`
- 内容表面：`#FFFFFF`
- 主文字：`#17191D`
- 主操作色：`#146C63`
- 提醒色：`#C84E3E`
- 边框：`#DCE1E7`

### 10.2 字体与组件

- 中文字体优先使用系统字体或 Noto Sans SC。
- 正文字号在移动端不小于 16px。
- 控件圆角不超过 8px。
- 主要触控区域不小于 44px。
- 所有交互元素提供键盘焦点状态。
- 错误、成功和次数不足不能只通过颜色表达，必须同时提供文字和图标。

### 10.3 标志性交互

兑换成功时可以使用一次简短的“兑换券盖章”动效，并立即更新右上角次数。其余页面动画保持克制，只用于状态变化和操作反馈。

## 11. 响应式要求

1. 支持 375px、768px、1024px 和 1440px 典型宽度。
2. 手机端采用单列操作流。
3. 桌面端可以使用左侧导航、中间图片区域和右侧参数面板。
4. 图片对比、批量上传和多结果查看以桌面体验为主。
5. 手机端不得出现横向页面滚动。
6. 固定顶部栏需要为页面内容预留空间。

## 12. 安全与隐私要求

1. 使用安全 Cookie 或等效安全会话机制，不把长期有效 Token 暴露给任意脚本。
2. 浏览器设备标识不能作为权益余额的唯一依据。
3. API Key 不得出现在前端构建产物和浏览器请求中。
4. 原始图片和生成结果需要明确保存期限。
5. 用户应能查看图片隐私说明。
6. 上传需要限制文件类型、单文件大小、文件数量和总大小。
7. 登录、兑换和收费提交需要服务端限流。
8. 兑换和消费操作需要保存服务端流水记录。

## 13. 验收标准

1. 用户可以使用邮箱和密码完成注册、登录和退出。
2. 注册成功后自动进入已登录但未兑换状态。
3. 用户可以在右上角输入兑换码并获得使用次数。
4. 同一个兑换码不能被重复兑换。
5. 清除浏览器缓存后，重新登录仍能恢复账号次数。
6. 多个页面同时提交时不能透支次数。
7. 所有收费按钮都能显示预计消耗并处理余额变化。
8. 次数不足时不丢失用户已经填写的任务内容。
9. 异步任务刷新页面后仍可继续查看进度。
10. 任务失败并退款后，页面能显示最新次数和退款记录。
11. 用户可以查看历史任务、结果和消费记录。
12. API Key 不出现在前端源码、LocalStorage 或浏览器网络请求中。
13. 页面能够在 375px 手机和 1440px 桌面宽度下正常使用。
