## 1. 项目背景

映研用户端面向咸鱼购买 AI 图片服务的用户，提供注册登录、兑换次数、提示词优化、
文生图、图生图、任务记录和人工修图申请。

管理端不能只承担人工修图工单处理，还需要成为整个平台的运营控制台，用于完成：

1. 生成、发放、失效和追踪咸鱼商品对应的兑换码。
2. 配置后端实际调用的 AI 服务商、API Key 和模型。
3. 管理用户账号、可用次数、兑换和消费流水。
4. 查看用户上传的原图、参考图、需求、提示词版本、任务和生成结果。
5. 处理用户提交的人工修图工单。
6. 记录所有敏感数据访问和管理操作。

AI 服务商的 Base URL、API Key 和模型配置只保存在服务端。用户端始终只调用映研
自己的 `/api` 接口，由后端选择当前生效的模型、执行 AI 请求并向 Client 返回任务和
图片结果。

## 2. 产品定位与目标

### 2.1 产品定位

映研平台管理端是一套桌面优先、面向平台所有者和人工修图操作员的内部运营工具。
它不是对外营销网站，也不是 AI 对话工具。

管理端首页应优先呈现需要立即处理的业务状态，例如即将过期的兑换码、待报价工单、
生成失败任务和 AI 服务异常，而不是展示装饰性数据。

### 2.2 核心目标

1. 让平台管理员安全、快速地生成并发放兑换码。
2. 保证兑换码核销、用户次数和流水始终保持事务一致。
3. 让平台管理员无需修改代码即可新增 `test1`、`test2` 等 AI 服务商及模型。
4. 保证全平台对话模型和生图模型各自只有一个当前生效项。
5. 让管理人员可以从用户、任务、素材、提示词和工单之间追溯完整业务链路。
6. 让人工修图操作员在最小数据权限下完成报价、修图和交付。
7. 让所有敏感操作均可审计、可定位、不可抵赖。

### 2.3 非目标

1. 本阶段不开发管理端页面。
2. 本阶段不实现后端、数据库、对象存储或任务队列。
3. 本阶段不编写完整的管理端 API 请求与响应契约。
4. 不实现在线支付、咸鱼订单自动同步或退款支付。
5. 不重复建设 AI 成本核算和 API 转发计费系统。
6. 不提供任意请求模板、脚本或代码执行能力。
7. 不支持按用户、套餐或用户组分配不同 AI 模型。
8. 不提供网页版 Photoshop 或直接修改数据库记录的通用工具。

## 3. 核心原则

1. **服务端可信**：权限、次数、核销、模型选择和资源归属都由后端校验。
2. **最小权限**：修图操作员只能访问工单处理所需的数据。
3. **历史不可篡改**：兑换、次数、任务、提示词和审计历史原则上只读。
4. **敏感信息不下发**：API Key、密码哈希、对象存储密钥和内部路径不得返回前端。
5. **管理写操作可追溯**：写操作必须记录操作人、原因、结果和请求追踪信息。
6. **危险操作明确确认**：失效兑换码、减少次数、停用用户和清理图片必须二次确认。
7. **Client 无感知**：切换 AI 服务商或模型不改变 Client 的请求路径与业务协议。
8. **在途任务稳定**：已提交任务使用创建时的模型快照，不跟随平台模型切换。
9. **不自动故障转移**：v0.1 不在 `test1`、`test2` 之间静默切换，避免结果和成本不可控。

## 4. 用户角色与权限

### 4.1 角色定义

#### 平台管理员

平台所有者或被授权的运营管理员，具备：

- 兑换码和生成批次管理权限。
- AI 服务商、API Key、模型和平台路由管理权限。
- 用户状态、密码重置和人工次数调整权限。
- 全部任务、提示词、图片、次数流水和工单查看权限。
- 人工修图工单处理权限。
- 图片保留和提前清理权限。
- 审计日志查看与导出权限。

#### 修图操作员

负责人工修图交付，具备：

- 人工修图工单列表和详情查看权限。
- 查看工单关联用户的基本信息。
- 查看和下载工单关联原图、参考图、AI 成片和返修要求。
- 报价、开工、上传交付、拒单和标记履约失败权限。

修图操作员不具备：

- 查看完整兑换码的权限。
- 查看或修改 AI 服务商和 API Key 的权限。
- 调整用户次数或重置密码的权限。
- 浏览与当前工单无关的用户图片、任务和提示词的权限。
- 清理平台图片或导出审计数据的权限。

### 4.2 权限矩阵

| 模块 | 平台管理员 | 修图操作员 |
| --- | --- | --- |
| Dashboard | 全部 | 仅工单相关 |
| 兑换码与批次 | 管理 | 不可访问 |
| AI 服务商与模型 | 管理 | 不可访问 |
| 用户和次数 | 管理 | 仅工单关联用户摘要 |
| 生成任务和提示词 | 全部只读 | 仅工单关联内容 |
| 图片资产 | 查看、下载、保留、清理 | 仅工单关联查看和下载 |
| 人工修图工单 | 管理 | 管理 |
| 审计日志 | 查看、导出 | 仅本人操作摘要 |

### 4.3 管理账号

- 管理端复用邮箱和密码登录，但不开放公开注册。
- 管理角色由后端或已有平台管理员授予。
- 公开注册接口只能创建普通用户，不能创建或提升管理身份。
- 管理会话恢复结果必须返回管理员角色和权限集合，供路由和菜单初始化。
- 普通 Client 用户即使已登录，也不能访问 `/api/manage/**`。
- 停用管理账号后，后端立即使其全部 Session 失效。
- 管理端不得提供查看密码、密码哈希或历史密码的能力。

## 7. 兑换码与生成批次

兑换码是管理端最高优先级的业务模块，承担咸鱼订单与平台使用次数之间的发放凭证。

### 7.1 核心数据对象

```ts
type RedemptionCodeStatus =
  | 'unused'
  | 'redeemed'
  | 'expired'
  | 'disabled'

interface RedemptionBatch {
  id: string
  name: string
  productCode: string
  quantity: number
  creditsPerCode: number
  expiresAt?: string
  neverExpires: boolean
  note?: string
  createdBy: string
  createdAt: string
}

interface RedemptionCode {
  id: string
  maskedCode: string
  batchId: string
  productCode: string
  credits: number
  status: RedemptionCodeStatus
  expiresAt?: string
  redeemedBy?: string
  redeemedAt?: string
  disabledBy?: string
  disabledAt?: string
  disabledReason?: string
  createdAt: string
}
```

完整兑换码属于敏感字段，不进入通用列表结构、审计内容或日志。

时间和商品约定：

- 所有创建、兑换、失效和过期时间使用 ISO 8601 UTC。
- 永久有效统一表示为 `expiresAt = null`，不使用特殊日期。
- v0.1 的商品标识来自服务端维护的产品集合，默认产品为 `yingyan-client`。
- Client 兑换请求仍只提交兑换码，后端根据当前 Client 产品上下文完成商品匹配。
- 管理员不能通过自由文本创建不存在的商品标识。

### 7.2 生成方式

管理端支持：

1. 单个生成。
2. 批量生成。

单个生成在数据层仍创建数量为 1 的批次，以保持生成规则、导出和审计逻辑一致。

创建时填写：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 批次名称 | 是 | 便于关联咸鱼商品或运营活动 |
| 生成数量 | 是 | 1 到 500 的整数 |
| 每码次数 | 是 | 大于 0 的整数 |
| 商品标识 | 是 | 用于校验兑换码对应的平台商品 |
| 有效期 | 是 | 默认创建后 90 天，可指定时间或永久有效 |
| 备注 | 否 | 记录用途，不向 Client 展示 |

生成规则：

- 完整码由服务端使用密码学安全随机数生成。
- 推荐展示格式为 `YY-XXXX-XXXX-XXXX`。
- 排除容易混淆的字符，例如 `0/O`、`1/I`。
- 核销时执行 `trim` 和大写标准化。
- 管理员不能手工指定或编辑完整兑换码。
- 同一完整码在数据库中必须唯一。
- 后端保存标准化兑换码摘要用于唯一校验和核销查找，同时保存加密密文用于授权查看。
- 数据库、日志和审计中均不得保存可直接搜索到的明文兑换码。
- 批量生成采用单个事务：全部成功或全部失败。
- 生成请求必须携带幂等键，网络重试不能产生重复批次。

### 7.3 生成结果

生成成功后展示：

- 批次名称和编号。
- 生成数量和每码次数。
- 商品标识和有效期。
- 完整兑换码列表。
- 复制单码、复制全部和导出 CSV。

关闭结果页后，平台管理员仍可在批次详情中重新查看或导出未使用完整码。

### 7.4 完整码的查看与导出

- 只有平台管理员可以请求完整兑换码。
- 修图操作员和其他无权限身份只能看到掩码，例如 `YY-****-****-A7K9`。
- 查看、复制单码、复制全部和导出都记录独立审计事件。
- 完整码不得写入浏览器持久缓存、前端日志、服务端普通日志或错误监控上下文。
- 完整码接口和导出响应设置 `Cache-Control: no-store`。
- CSV 为即时生成文件，不在服务器长期保存。
- CSV 至少包含完整码、批次、次数、商品标识、状态和有效期。
- 数据库存储应同时满足安全核销查询和授权重新显示；具体加密方案由后端设计确定。

### 7.5 兑换码列表

列表字段：

- 掩码兑换码。
- 批次名称。
- 商品标识。
- 可兑换次数。
- 当前状态。
- 有效期。
- 兑换用户邮箱。
- 兑换时间。
- 创建时间。

筛选项：

- 兑换码关键词。
- 批次。
- 商品标识。
- `unused`、`redeemed`、`expired`、`disabled` 状态。
- 创建时间和过期时间。
- 兑换用户邮箱。
- 7 天内即将过期。

列表快捷操作：

- 复制未使用完整码。
- 查看详情。
- 失效未使用码。
- 延长未使用码的有效期。

### 7.6 批次列表和详情

批次列表展示：

- 批次名称和编号。
- 总数量。
- 未使用、已兑换、已失效、已过期数量。
- 使用率。
- 每码次数。
- 商品标识。
- 有效期。
- 创建人和创建时间。

批次详情支持：

- 查看批次配置和状态分布。
- 查看本批次全部兑换码。
- 复制或导出未使用码。
- 批量失效未使用码。
- 批量延长未使用、非显式失效码的有效期。

### 7.7 状态机

```text
unused
  ├─ 用户成功兑换 -> redeemed
  ├─ 到达 expiresAt -> expired
  └─ 管理员手动失效 -> disabled

expired
  └─ 管理员延长有效期 -> unused

redeemed  -> 终态
disabled  -> 终态
```

约束：

- 状态显示优先级固定为：已兑换、手动失效、过期、未使用。
- 存在 `redeemedAt` 时永远显示 `redeemed`。
- 未兑换但存在 `disabledAt` 时显示 `disabled`。
- 未兑换、未失效且服务端当前时间达到 `expiresAt` 时显示 `expired`。
- `redeemed` 不允许撤销、失效或延期。
- `disabled` 不允许恢复，只能生成新码。
- `expired` 只有在未兑换且未被手动失效时允许延期。
- 永久有效兑换码没有 `expired` 状态。
- 状态变化必须由服务端重新校验，不能信任列表中的旧状态。

### 7.8 单个和批量失效

失效操作必须：

1. 二次确认。
2. 展示所选数量及实际可失效数量。
3. 要求填写失效原因。
4. 携带幂等键。
5. 返回成功、跳过和失败数量。
6. 记录操作人、原因、目标批次或兑换码和时间。

批量失效只修改当前仍为 `unused` 的兑换码：

- `redeemed` 保持已核销，不退回用户次数。
- `expired` 保持过期。
- `disabled` 视为已经处理。

如需收回用户次数，平台管理员必须进入用户详情执行单独的人工次数调整，不能通过兑换码
失效隐式扣减。

### 7.9 过期和延期

- 默认过期时间为创建时间后 90 天。
- 创建时可指定其他未来时间或选择永久有效。
- 过期状态由服务端时间判断，前端倒计时只用于提示。
- 7 天内过期的未使用码标记为“即将过期”。
- 支持对单码或批次中的可延期兑换码设置新的未来时间。
- 延期需要二次确认和操作原因。
- 已兑换码的历史有效期不随批次延期改变。
- 永久有效切换和取消也属于需要审计的管理写操作。

### 7.10 用户兑换的事务规则

用户提交 `POST /api/redemptions/claim` 时，后端必须在同一个数据库事务中：

1. 标准化兑换码。
2. 锁定兑换码记录和用户次数账户。
3. 校验兑换码存在且状态为 `unused`。
4. 校验未过期、未失效且商品匹配。
5. 标记兑换码为 `redeemed` 并记录用户与时间。
6. 增加用户可用次数。
7. 写入不可修改的兑换流水。
8. 提交事务并返回最新余额。

并发请求不能重复核销。同一幂等键重试返回第一次成功结果。
兑换与管理端失效并发时，只有首先取得锁并满足状态条件的一方成功，不能同时产生
`redeemed` 和 `disabled` 结果。

Client 错误表现保持：

- 不存在或已手动失效：继续返回现有 `3001 CODE_INVALID`。
- 已兑换：兑换码已使用。
- 已过期：兑换码已过期。
- 商品不匹配：兑换码不适用于当前商品。

## 8. AI 服务商与模型

### 8.1 数据关系

```text
AIProvider 1 ─── N AIModel

全平台唯一 PlatformChatModel  -> 某个 chat 模型
全平台唯一 PlatformImageModel -> 某个 image 模型
```

服务商负责连接信息，模型负责实际模型 ID、类型、能力和平台用途。相同服务商下新增多个
模型时不重复保存 Base URL 和 API Key。

### 8.2 服务商配置

服务商字段：

| 字段 | 说明 |
| --- | --- |
| 名称 | 管理端展示名称，例如 `test1` |
| 编码 | 唯一稳定标识，创建后不可随意修改 |
| 协议类型 | v0.1 固定为 OpenAI Compatible |
| Base URL | 服务端请求地址 |
| API Key | 加密保存的访问密钥 |
| 启用状态 | 是否允许平台调用 |
| 连接状态 | 未测试、正常、异常 |
| 最近测试 | 时间、结果和脱敏错误摘要 |
| 备注 | 内部用途说明 |

安全要求：

- 启用状态和连接健康状态是两个独立字段。
- API Key 创建或轮换时可输入，保存后只返回掩码。
- 管理端无法重新读取完整 API Key。
- API Key 不进入日志、审计变更快照和错误上报。
- 覆盖 API Key 必须二次确认并记录操作人。
- 修改 Base URL 或 API Key 后，旧连接测试立即失效，重新测试成功前不能用于新绑定。
- Base URL 默认只接受 HTTPS，并拒绝回环、内网、链路本地和云元数据地址，防止 SSRF。
- 删除服务商前必须确认其没有当前生效模型和在途任务引用。

### 8.3 模型配置

模型字段：

- 展示名称。
- 服务商返回或文档要求的实际模型 ID。
- 模型类型：`chat` 或 `image`。
- 启用状态。
- 连接测试状态。
- 能力标签。
- 创建和更新时间。

`chat` 模型能力：

- 提示词优化。
- 后续扩展的管理端文本能力。

`image` 模型能力：

- 文生图。
- 图生图或图片编辑。

由于 v0.1 全平台只有一个生图模型绑定，该模型必须同时通过文生图和图生图能力测试后
才能开启平台生图模型滑块。后续如需分别绑定两种能力，应升级平台绑定模型，而不是在
运行时静默选择其他服务商。

模型类型创建后不直接修改。需要变更类型时创建新模型并停用旧模型，避免历史任务含义
发生变化。

### 8.4 平台模型滑块

当模型类型为 `chat` 时显示：

```text
作为生图平台的对话模型
```

当模型类型为 `image` 时显示：

```text
作为生图平台的生图模型
```

规则：

- 每种类型全平台最多一个模型开启。
- 开启新模型时，后端在同一事务内关闭同类型旧模型。
- 两名管理员并发切换同类型模型时，数据库唯一约束仍须保证最终只有一个绑定。
- 开启前显示将被替换的模型。
- 未测试、测试失败、被停用或所属服务商被停用的模型不能开启。
- 修改模型 ID 或能力后，旧测试结果立即失效，模型需要重新测试。
- 停用当前服务商或模型前必须先切换或解除其平台绑定。
- 关闭当前平台模型后，对应能力进入“未配置”状态。
- 管理端明确提示未配置会导致 Client 对应操作暂不可用。

### 8.5 连接和能力测试

- 服务商支持“测试连接”。
- 模型支持按具体模型执行“测试模型”。
- 聊天模型使用最小文本请求验证认证、模型 ID 和响应结构。
- 生图模型测试需要明确提示可能产生服务商费用。
- 测试由后端发起，浏览器不得直接请求服务商。
- 测试请求同样执行出站地址校验、超时和响应大小限制。
- 错误信息需要脱敏，不能包含 API Key、完整请求头或服务商敏感响应。

### 8.6 后端调用路由

- 提示词优化使用当前平台对话模型。
- 文生图和图生图使用当前平台生图模型。
- 后端根据模型能力判断是否支持当前请求。
- 任务创建时保存服务商 ID、模型 ID 和配置版本快照。
- 任务快照不复制 API Key。密钥轮换后，在途任务使用服务商当前有效密钥继续执行。
- 在途任务继续使用创建时快照，不跟随平台配置变更。
- v0.1 不进行自动故障转移；服务商失败时按当前任务失败和退款规则处理。
- Client 只接收任务状态、结果和脱敏错误，不接收服务商连接信息。

异常场景：

- 无当前模型：返回平台能力暂不可用。
- 当前模型被停用：拒绝创建新任务，保留用户草稿且不扣次数。
- 服务商超时或失败：按任务结算规则退款。
- 模型不支持图生图：在报价或最终提交前拒绝请求。

## 9. 人工修图工单

人工工单沿用现有 [管理端 API 契约](../frontApi/serverApi.md) 和状态机。

### 9.1 列表和详情

- 按状态、工单号、任务标题和用户邮箱筛选。
- 详情集中展示用户要求、来源任务、原图、参考图、AI 成片、补充素材和时间线。
- 修图操作员只能访问被授权工单及其关联数据。
- v0.1 不做工单分派，具备 `retouch:manage` 权限的人员共享工单队列。
- 多人同时处理时依靠后端状态锁和幂等规则阻止覆盖。

### 9.2 管理操作

- `submitted`：评估并报价，或拒绝接单。
- `quote_pending`：用户接受前允许重新报价。
- `accepted`：确认开工并结算预占次数。
- `processing`：上传人工成片并交付。
- `awaiting_confirmation`：等待用户确认或一次返修。
- 履约失败：关闭工单并按规则退款。

报价、开工、交付、拒单和退款均需要幂等键、状态校验和审计日志。
现有 `rejected` 同时承载开工前拒单和履约失败，管理端必须结合时间线动作及
`refundedCredits` 区分，不自行新增不兼容状态。

## 10. 用户、账号和次数

### 10.1 用户列表

支持按以下条件检索：

- 用户 ID 或邮箱。
- `active`、`disabled` 状态。
- 注册时间。
- 最近登录时间。
- 当前次数区间。
- 是否有生成任务或人工工单。

列表展示用户邮箱、状态、当前次数、累计兑换、累计消费、任务数量和注册时间。

### 10.2 用户详情

用户详情包含：

- 基本账号信息和状态。
- 当前可用次数。
- 兑换记录。
- 消费、退款和人工调整流水。
- 生成任务。
- 图片资产。
- 人工修图工单。
- 最近登录和管理操作记录。

不得展示用户密码或密码哈希。

### 10.3 启用和停用

- 停用用户必须填写原因并二次确认。
- 停用后立即使登录 Session 失效。
- 停用用户不能登录、兑换、提交生成任务或创建工单。
- 停用不删除历史任务、图片、次数和流水。
- 重新启用需要记录操作人和原因。

### 10.4 安全重置密码

- 管理员只能发起重置，不能设置或查看用户原密码。
- 后端生成一次性临时密码。
- 完整临时密码只展示一次，并设置短有效期。
- 用户下次登录后必须设置新密码。
- 重置操作使旧 Session 失效并写入审计日志。
- 该流程需要后续同步补充 Client 的强制改密页面和认证接口。

### 10.5 人工次数调整

平台管理员可以增加或减少用户次数。

必填字段：

- 调整数量，正数表示增加，负数表示减少。
- 调整原因。
- 可选关联编号，例如咸鱼订单号或工单号。

规则：

- 调整后余额不能小于 0。
- 请求必须携带幂等键。
- 流水增加 `adjustment` 类型，并记录调整前余额、调整后余额、操作人和原因。
- 余额、流水和审计记录在同一个事务中提交。
- 人工调整流水不可编辑或删除。
- 减少次数不能伪装成兑换码撤销。
- 后续必须同步更新 Client 流水类型和展示文案，不能把人工调整伪装成退款或兑换。

## 11. 生成任务、提示词和图片

### 11.1 生成任务列表

支持按用户、任务 ID、模式、状态、时间、服务商和模型筛选。

列表展示：

- 用户邮箱。
- 任务标题和模式。
- 当前状态与进度。
- 请求、成功和失败图片数量。
- 预占、消费和退款次数。
- 实际服务商和模型。
- 创建和更新时间。
- 是否有关联人工工单。

### 11.2 任务详情

详情需要完整还原用户提交时的上下文：

- 用户原始生图或修图要求。
- 原始图片。
- 参考图片及风格、构图、人物、细节用途。
- 提示词优化前的原始内容。
- 优化后的分区提示词。
- 用户最终确认的提示词版本。
- 图片比例、输出数量和参考强度。
- 服务商与模型快照。
- 任务状态、进度、错误和次数结算。
- AI 生成结果。
- 关联人工修图工单。

任务业务数据只读，管理端不能直接修改提示词、状态、次数字段或生成结果。
服务商、模型和配置版本只增加在管理端任务详情 DTO 与后端执行记录中，不向 Client
返回 Base URL、API Key 或内部路由信息。

### 11.3 图片资产

图片分类：

- 用户原图 `source`。
- 创作参考图 `reference`。
- 人工修图补充图 `retouch-reference`。
- AI 生成结果。
- 人工修图交付结果。

支持按用户、任务、工单、图片类型、上传时间和到期时间筛选。

安全要求：

- 预览和下载使用短期签名 URL。
- 不返回对象存储内部路径、Bucket 密钥或永久公开地址。
- 签名过期后允许刷新，不将过期误判为资源已删除。
- 下载敏感图片需要权限校验和访问审计。

### 11.4 图片留存

- 任务进入终态后默认保留 90 天。
- 存在关联人工工单时，从最后一个关联工单进入终态后重新计算 90 天留存期。
- 平台管理员可以标记“长期保留”，阻止自动清理。
- “长期保留”表示取消自动清理，直至平台管理员主动解除。
- 解除长期保留需要原因和审计。
- 提前清理必须确认图片不再被运行中任务或工单使用。
- 提前清理不可恢复，需要展示明确影响范围。
- 图片删除后保留业务元数据和审计记录，但不保留可访问文件地址。

## 12. 审计日志

### 12.1 必须审计的事件

- 完整兑换码查看、复制和导出。
- 兑换码或批次生成、失效和延期。
- AI 服务商创建、修改、启停和 API Key 轮换。
- 模型创建、启停、测试和平台模型切换。
- 用户启停、密码重置和次数调整。
- 图片下载、长期保留和提前清理。
- 工单报价、开工、交付、拒单和退款。
- 管理角色和权限变更。

### 12.2 日志字段

- 审计 ID。
- 操作管理员和角色。
- 动作类型。
- 目标类型和目标 ID。
- 脱敏后的变更前后摘要。
- 操作原因。
- 成功或失败结果。
- `X-Request-Id`。
- 操作时间。
- 必要时记录 IP 和设备摘要。

审计日志只追加，不允许管理端编辑或删除。API Key、完整兑换码、密码和签名 URL 不得
进入审计详情。成功和失败操作均写入审计，在线审计记录至少保留 365 天。

## 13. API 边界

### 13.1 通用协议

成功响应：

```ts
interface ApiSuccessResponse<T> {
  code: 0
  data: T
}
```

错误响应：

```ts
interface ApiErrorResponse {
  code: number
  message: string
  details?: unknown
}
```

通用要求：

- 管理接口统一使用 `/api/manage` 前缀。
- 认证采用安全 Cookie Session。
- 管理会话数据至少包含管理员 ID、角色和权限集合。
- 所有接口执行服务端权限校验。
- 列表使用统一分页结构。
- 所有管理写接口必须携带 `Idempotency-Key`。
- 敏感写接口需要防 CSRF、限流和审计。
- 请求追踪 ID 通过请求和响应头传递。
- 现有 `serverApi.md` 只校验 `retouch:manage`；扩展管理接口时需要增加平台管理权限。
- 人工次数调整引入 `adjustment` 流水类型时，需要同步更新
  [用户端 API 契约](../frontApi/clientApi.md)。

### 13.2 后续接口领域

后续扩展 `frontApi/serverApi.md` 时，至少覆盖：

- `/api/manage/redemption-batches`
- `/api/manage/redemption-codes`
- `/api/manage/ai-providers`
- `/api/manage/ai-models`
- `/api/manage/platform-model-bindings`
- `/api/manage/users`
- `/api/manage/usage-ledger`
- `/api/manage/generation-tasks`
- `/api/manage/assets`
- `/api/manage/audit-logs`
- 现有 `/api/manage/retouch-tickets`

本 PRD 只确定产品行为和接口领域，详细方法、路径参数、请求体、响应结构和错误码在管理端
API 文档中单独维护。

## 14. 通用异常和反馈

管理端至少覆盖：

- 登录失效或权限不足。
- 数据已被其他管理员修改。
- 重复提交或幂等键冲突。
- 批量生成兑换码失败。
- 兑换码已被核销，无法失效。
- 批量操作部分记录状态不允许。
- 用户次数不足，无法减少。
- 服务商连接失败或超时。
- 模型 ID 不存在或能力不匹配。
- 当前平台模型缺失。
- 签名图片地址过期。
- 图片仍被运行中任务或工单使用。
- 工单状态已经变化。

失败反馈必须说明：

1. 哪项操作没有完成。
2. 为什么无法完成。
3. 用户可以采取什么下一步。
4. 批量操作中成功、跳过和失败的数量。

## 15. 交互和视觉要求

1. 管理端采用安静、密集、便于扫描的运营工具布局。
2. 不制作营销 Hero，不使用聊天机器人作为主界面。
3. 表格、筛选栏、详情抽屉和批量操作栏保持稳定尺寸。
4. 状态同时使用文字和颜色，不只依赖颜色区分。
5. 兑换码完整值、API Key、用户图片等敏感内容默认隐藏。
6. 删除、失效、停用、扣次和模型切换使用明确确认弹窗。
7. 按钮文案描述实际结果，例如“失效 12 个未使用兑换码”。
8. 桌面端优先，平板支持完整查询和处理，手机端保证关键查看与待办处理可用。
9. 所有表单有可见标签、错误文字、键盘焦点和加载状态。
10. 触控区域不小于 44px，支持 reduced-motion。

## 16. 安全与隐私

1. API Key 必须加密保存并且不可从管理 API 重新读取。
2. 完整兑换码只向平台管理员按需返回，并禁止缓存和日志记录。
3. 密码、密码哈希和一次性重置凭证不得进入日志。
4. 管理 Session 使用安全 Cookie，并具备合理超时和主动失效能力。
5. 用户图片和生成结果使用短期签名地址。
6. 所有资源查询均校验当前角色和资源范围。
7. 停用管理员或用户时立即吊销现有 Session。
8. 管理写接口需要幂等、防 CSRF、限流和请求审计。
9. 数据导出应标记导出人和时间，不在服务端长期保留。
10. 生产环境 Base URL 默认要求 HTTPS。
11. 服务商连接测试必须阻止访问本机、内网、链路本地和云元数据地址。
12. 审计日志成功与失败操作至少保留 365 天。

## 17. 验收标准

### 17.1 兑换码

1. 平台管理员可以生成 1 到 500 个唯一兑换码。
2. 默认有效期为 90 天，同时支持指定到期时间和永久有效。
3. 同一个生成请求重试不会产生重复批次。
4. 未使用完整码可以按权限查看、复制和导出。
5. 修图操作员无法访问兑换码模块或完整码。
6. 未使用码可以单个或批量失效。
7. 已兑换码不能撤销，也不会因批次失效收回用户次数。
8. 过期未使用码可以延期，显式失效码不能恢复。
9. 兑换码核销、用户余额和次数流水在同一个事务中完成。
10. 完整码查看、导出、失效和延期均存在审计记录。
11. 两个用户并发兑换同一码时只有一个成功。
12. 兑换和失效并发时只有一个合法状态转换获胜。
13. 一次生成 500 个码必须全部成功或全部失败，标准化后仍全局唯一。
14. 过期边界、永久有效、延期恢复和手动失效不可恢复符合状态优先级。

### 17.2 AI 服务

1. 平台管理员可以新增 `test1` 服务商并保存 Base URL 和 API Key。
2. 一个服务商下可以新增多个聊天或生图模型。
3. 聊天模型只显示对话模型平台滑块。
4. 生图模型只显示生图模型平台滑块和图片能力。
5. 全平台对话模型和生图模型各自最多一个生效。
6. 未通过测试或被停用的模型不能设为平台模型。
7. 模型切换不影响已经提交的任务。
8. Client 无法获取服务商 Base URL、API Key 或路由规则。
9. 两名管理员并发开启同类型模型后，数据库仍只有一个平台绑定。
10. 修改 Base URL、API Key 或模型 ID 后，旧测试状态立即失效。
11. 当前生图模型必须同时支持文生图和图生图。
12. 无可用模型、超时、部分失败和全部失败均遵循现有任务退款规则。

### 17.3 用户和平台数据

1. 平台管理员可以查询、启停用户和发起安全密码重置。
2. 人工增减次数要求原因，不能产生负余额，并写入不可修改流水。
3. 管理端可以关联查看用户、兑换、任务、素材、提示词、结果和工单。
4. 任务和提示词历史不能被管理端直接篡改。
5. 图片默认按 90 天规则清理，活动工单会顺延。
6. 图片提前清理和长期保留均有权限校验、确认和审计。
7. 人工次数调整并发执行时不会产生负余额或重复流水。
8. Client 能正确展示新增的 `adjustment` 流水。

### 17.4 工单和审计

1. 人工工单支持报价、开工、交付、返修、拒单和履约失败退款。
2. 修图操作员只能查看处理工单所需的数据。
3. 所有敏感查看和管理写操作可按管理员、目标、动作和时间追溯。
4. API Key、完整兑换码、密码和签名 URL 不出现在审计详情中。
5. 普通用户和修图操作员直接请求越权管理接口均返回 `403/1003`。
6. 修图操作员无法读取非关联任务、提示词、图片或用户次数流水。
7. 提前清理会阻止运行中任务和非终态工单，并保留元数据与审计。
